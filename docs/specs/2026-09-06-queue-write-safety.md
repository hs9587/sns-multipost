# 監視・キュー書込みの排他と原子的保存

- 日付: 2026-09-06
- 状態: 実装・自動テスト完了

## 方針

`watch`、`post`、`run_queue`、`retry` は同じプロセスロックを使う。別の処理がキューまたは
監視基準を操作中なら、後から起動したコマンドは処理せず `skip` を表示する。定期実行では次回に
改めて監視されるため、ロック待ちで実行時間を延ばさない。

ジョブJSONと `state/since_id.txt` は、同じディレクトリの一時ファイルへ全内容を書き、flushと
fsyncを終えてからrenameで確定する。プロセス終了やPC停止が書込み途中に起きても、本来の名前で
途中までのJSONや空の監視基準を残さない。

## 今回の範囲外

一つのFedibird投稿から複数投稿先のジョブを作る途中で停止した場合、監視基準は前進しない。
次回監視で同じ投稿を再検出できる一方、停止前に完成していた投稿先のジョブが重複する可能性は
残る。投稿先単位の安定した識別子による重複抑止は、次の独立した安定化項目とする。
