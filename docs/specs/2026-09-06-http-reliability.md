# API通信のタイムアウトと安全な再試行

- 日付: 2026-09-06
- 状態: 実装・自動テスト完了
- 対象: Fedibird、Bluesky、Tumblr、Blogger、Threads、X、OAuth更新

## 方針

API通信が応答しないまま定期タスクを占有し続けないよう、共通HTTP処理に接続10秒、読取り30秒、
書込み30秒の上限を設定する。一時障害の再試行は初回を含め最大3回、待ち時間は1秒、2秒とする。

二重投稿を避けるため、再試行の可否はリクエストの性質と失敗位置で分ける。

- GET、HEAD、PUT、DELETE等の冪等な処理は、一時的な通信例外とHTTP 408、425、429、
  500、502、503、504を自動再試行する
- POSTは、DNS解決失敗、接続開始タイムアウト、接続拒否など、サーバーへ未送信と判断できる
  接続前の失敗だけを自動再試行する
- POST送信後の読取りタイムアウト、接続リセット、HTTPエラー応答は、投稿が成立済みの可能性が
  あるため自動再試行しない。ジョブを `failed/` に残し、投稿先を確認してから手動判断する

画像URLの取得にも接続10秒、読取り30秒の上限を設定する。画像取得は今回の共通再試行対象には
含めず、失敗時は次回の監視または手動再試行で扱う。

## 実装

- `lib/http_transport.rb`: タイムアウト、再試行可否、1秒・2秒のバックオフ
- 各APIクライアントの既定transportを共通処理へ統一
- `lib/media.rb` と `lib/blogger_image_store.rb`: 公開画像取得の時間上限

再試行時のログにはHTTPメソッドと接続先ホストだけを表示し、パス、クエリ、トークンは表示しない。
